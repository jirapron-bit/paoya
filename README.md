# เป๋ายา (PAOYA) เวอร์ชัน 2

ผู้ช่วยดูแลเรื่องยา: ค้นหายาจากบัญชียาหลักแห่งชาติ บันทึกยาประจำ นัดหมาย สต็อกยา ประวัติแพ้ยา บันทึกสุขภาพ สแกนฉลากยา และแชทกับเภสัชกร AI

ต่อยอดจาก `paoya_hybrid_application.html` เดิม โดยหน้าตาและเมนูยังเหมือนเดิม แต่ตอนนี้มี **backend จริง** ข้อมูลทุกอย่างจึงบันทึกลงฐานข้อมูลและไม่หายเมื่อรีเฟรช

## มีอะไรใหม่เทียบกับเวอร์ชันเดิม

| เรื่อง | เดิม | ใหม่ |
|---|---|---|
| สมัคร / เข้าสู่ระบบ | กดแล้วเข้าได้เลย ไม่ตรวจรหัส | ตรวจรหัสผ่านจริง เข้ารหัสด้วย scrypt ใช้ cookie แบบ httpOnly และสั่งออกจากระบบจากเซิร์ฟเวอร์ได้ (ดูหัวข้อ "ระบบความปลอดภัย") |
| ลืมรหัสผ่าน | หน้าจำลอง | สร้างลิงก์รีเซ็ตจริง ใช้ได้ 30 นาที |
| ข้อมูลยา | โหลด Excel ในเบราว์เซอร์ | เก็บในฐานข้อมูล ค้นหาผ่าน API แยกตามหมวดหมู่ได้ |
| รายละเอียดยา | มีข้อความตัวอย่างของพาราเซตามอลปนอยู่ | แสดงเฉพาะข้อมูลจริงจากบัญชียาหลัก |
| ยาประจำ / นัดหมาย / แพ้ยา / สุขภาพ | หายทุกครั้งที่รีเฟรช | บันทึกลงฐานข้อมูลแยกตามผู้ใช้ |
| บันทึกสุขภาพ | ปุ่มยังไม่ทำงาน | บันทึกความดัน ชีพจร น้ำตาลได้ พร้อมสีบอกระดับ |
| เตือนแพ้ยา | ไม่มี | เตือนอัตโนมัติเมื่อเปิดดูหรือเพิ่มยาที่ตรงกับยาที่แพ้ |
| ติดดาว / ประวัติการดู | ติดดาวยังไม่ทำงาน | ทำงานจริงและบันทึกไว้ |
| แชทเภสัชกร AI | ตอบตามคำที่กำหนดไว้ไม่กี่คำ | ใช้ Gemini ได้ (รู้ประวัติแพ้ยาและยาประจำของผู้ใช้) หรือใช้โหมดพื้นฐาน |
| สแกนฉลาก | ต้องใส่ API key ในเบราว์เซอร์ และถ้าไม่มี key จะแสดงผลสมมติ | key อยู่ที่เซิร์ฟเวอร์ ไม่มี key ก็ยังจับคู่ชื่อยาจากข้อความบนฉลากได้ และอัปโหลดรูปได้ |
| ร้านยา | รายชื่อร้านและราคาสมมติ | แผนที่ตามตำแหน่งจริง และรายการยาที่ต้องซื้อเติม |
| โหมดตัวอักษรใหญ่ / แจ้งเตือน | ไม่บันทึก | บันทึกในบัญชีผู้ใช้ |

## วิธีรันบนเครื่อง

ต้องมี **Node.js 22.13 ขึ้นไป** (ดาวน์โหลดได้ที่ https://nodejs.org แนะนำรุ่น LTS) ตรวจเวอร์ชันด้วยคำสั่ง `node -v`

```bash
# 1) ติดตั้งแพ็กเกจ
npm install

# 2) สร้างไฟล์ตั้งค่า
cp .env.example .env        # Windows: copy .env.example .env
# จากนั้นเปิด .env แล้วเปลี่ยน JWT_SECRET เป็นข้อความสุ่มยาว ๆ

# 3) เปิดเซิร์ฟเวอร์
npm start
```

แล้วเปิด http://localhost:3000 ในเบราว์เซอร์ ตอนเปิดครั้งแรก ระบบจะสร้างฐานข้อมูล `data/paoya.db` และโหลดข้อมูลยา 1,360 รายการให้อัตโนมัติ

- ระหว่างแก้โค้ดฝั่งเซิร์ฟเวอร์ ให้ใช้ `npm run dev` เซิร์ฟเวอร์จะรีสตาร์ทเองทุกครั้งที่บันทึกไฟล์
- ถ้าแก้หน้าเว็บ (ไฟล์ใน `public/`) แค่รีเฟรชเบราว์เซอร์ ไม่ต้อง build

### เปิดใช้เภสัชกร AI และสแกนยาด้วย AI (ไม่บังคับ)

เลือกใช้ได้ 3 ทาง ใส่ key ใน `.env` อย่างใดอย่างหนึ่ง

| ทาง | ค่าใช้จ่าย | วิธี |
|---|---|---|
| **Groq** (แนะนำ) | ฟรี ไม่ต้องผูกบัตร (จำกัดจำนวนครั้งต่อนาที/วัน) | สมัครที่ https://console.groq.com/keys แล้วใส่ `GROQ_API_KEY=gsk_...` |
| Google Gemini | บางบัญชีต้องเปิด billing | https://aistudio.google.com/apikey แล้วใส่ `GEMINI_API_KEY=...` |
| OpenAI-compatible (OpenRouter, GitHub Models, OpenAI) | แล้วแต่บริการ | ใส่ `AI_BASE_URL=...` และ `AI_API_KEY=...` |

ตรวจว่า key ใช้ได้ด้วย `npm run check-ai` (ทดลองทั้งถามคำถามและส่งรูป บอกสาเหตุถ้าใช้ไม่ได้) แล้วรีสตาร์ทเซิร์ฟเวอร์ ผู้ให้บริการเปลี่ยนรุ่นโมเดลบ่อย แอปจึงมีรุ่นสำรองและสลับให้เอง หรือกำหนดเองด้วย `AI_MODEL=` ถ้าไม่ใส่ key เลย แชทจะตอบคำถามพื้นฐานได้ และสแกนจะจับคู่ชื่อยาจากตัวหนังสือบนฉลาก

**สแกนยาด้วย AI:** ถ่ายภาพแผงยา ซอง กล่อง หรือขวดยา (เอียงหรือมีแสงสะท้อนได้) แล้ว AI จะบอกชื่อยา ชื่อการค้า ความแรง ใช้รักษาอะไร วิธีใช้ทั่วไปสำหรับผู้ใหญ่ วิธีใช้ที่พิมพ์บนฉลาก (ถ้ามี) ผลข้างเคียง และข้อควรระวัง พร้อมเตือนถ้าตรงกับยาที่ผู้ใช้แพ้ และกดเพิ่มเป็นยาประจำได้ทันที ถ้า AI ไม่มั่นใจว่าเป็นยาอะไร ระบบจะไม่แสดงวิธีใช้ เพื่อกันไม่ให้ผู้ใช้ทำตามข้อมูลของยาผิดตัว

### กล้องสแกนบนมือถือ

เบราว์เซอร์อนุญาตให้ใช้กล้องเฉพาะบน `https://` หรือ `localhost` ถ้าเปิดจากมือถือผ่าน IP ในวง LAN (เช่น `http://192.168.1.5:3000`) กล้องจะไม่ทำงาน แต่ยังใช้ปุ่ม "อัปโหลดรูป" แทนได้

## ใช้เป็นแอปบนมือถือและ iPad

เป๋ายาเป็นแอปแบบ **PWA (Progressive Web App)** ติดตั้งจากเบราว์เซอร์ลงหน้าจอโฮมได้เลย ไม่ต้องผ่าน App Store หรือ Play Store เปิดแล้วเต็มจอ มีไอคอนของตัวเอง และใช้กล้องสแกนฉลากได้

- **มือถือ:** ใช้เมนูด้านล่าง
- **iPad / จอใหญ่ (กว้าง 768px ขึ้นไป):** เปลี่ยนเป็นเมนูด้านซ้าย รายการยาแสดง 2 คอลัมน์ และแชท AI เปิดเป็นแผงด้านขวา ใช้ได้ทั้งแนวตั้งและแนวนอน
- รองรับรอยบากและแถบโฮมของ iPhone และกันไม่ให้หน้าจอซูมเองเวลาแตะช่องกรอก

> ⚠️ การติดตั้งเป็นแอปและการใช้กล้องต้องเปิดผ่าน **https** (หรือ `localhost` บนเครื่องเดียวกัน) จึงต้อง deploy ก่อน ถึงจะติดตั้งลงมือถือจริงได้

**วิธีติดตั้ง** (ในแอปก็มีคำแนะนำ ที่ ตั้งค่า → ติดตั้งแอปบนเครื่องนี้)

| อุปกรณ์ | วิธี |
|---|---|
| iPhone / iPad | เปิดเว็บใน Safari → แตะปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม" → "เพิ่ม" |
| Android | เปิดใน Chrome → แตะปุ่ม "ติดตั้ง" ในแอป หรือเมนู ⋮ → "ติดตั้งแอป" |
| คอมพิวเตอร์ (Chrome/Edge) | กดไอคอนติดตั้งที่ช่อง URL |

**ทดสอบบนมือถือก่อน deploy:** ให้มือถือกับคอมพิวเตอร์ต่อ Wi-Fi เดียวกัน แล้วเปิด `http://<IP ของคอม>:3000` (ดู IP ได้ด้วยคำสั่ง `ipconfig` บน Windows) วิธีนี้ดูหน้าตาได้ แต่ยังติดตั้งเป็นแอปไม่ได้ และกล้องจะไม่ทำงาน ถ้าอยากลองครบทุกอย่าง ใช้ tunnel ที่ให้ https เช่น `npx cloudflared tunnel --url http://localhost:3000` (ระหว่างใช้ tunnel ให้ตั้ง `TRUST_PROXY=1`)

**ไฟล์ที่เกี่ยวข้อง**
- `public/manifest.webmanifest`: ชื่อแอป ไอคอน สีธีม
- `public/sw.js`: service worker ที่เก็บไฟล์หน้าเว็บไว้ ทำให้เปิดเร็วขึ้น และขึ้นหน้า "ไม่มีอินเทอร์เน็ต" เมื่อออฟไลน์ ข้อมูลส่วนตัวจาก `/api` ไม่ถูกเก็บในแคช ถ้าเพิ่มไฟล์ .jsx ใหม่ ให้เพิ่มชื่อไฟล์ในรายการ `APP_SHELL` และเปลี่ยนเลข `VERSION`
- `public/icons/`: ไอคอนทุกขนาด สร้างจากโลโก้เดิม

**อยากขึ้น App Store / Play Store:** นำเว็บนี้ไปห่อด้วย [Capacitor](https://capacitorjs.com) ได้ ต้องมี Mac + Xcode และบัญชี Apple Developer (99 USD/ปี) สำหรับ iOS และบัญชี Google Play Console (25 USD ครั้งเดียว) สำหรับ Android

## อัปเดตข้อมูลยา

ถ้ามีไฟล์บัญชียาชุดใหม่ ให้วางทับ `data/datadrug.xlsx` (ชื่อคอลัมน์ต้องเหมือนเดิม) แล้วรัน

```bash
pip install pandas openpyxl
python scripts/import_xlsx.py
npm run reset-medicines
```

คำสั่งสุดท้ายจะล้างข้อมูลยาเดิมแล้วโหลดชุดใหม่เข้าไปแทน รายการติดดาวและประวัติการดูของผู้ใช้จะถูกล้างด้วย ส่วนข้อมูลอื่นของผู้ใช้ยังอยู่ครบ

## API

ทุกเส้นทางที่มี 🔒 ต้องเข้าสู่ระบบก่อน หน้าเว็บใช้ cookie ให้อัตโนมัติ ส่วนแอปอื่น (เช่น แอปมือถือ) ให้ส่ง `{ "wantToken": true }` ตอน login เพื่อรับ token แล้วแนบ header `Authorization: Bearer <token>` ทุกครั้ง

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| POST | `/api/auth/register` | สมัครสมาชิก |
| POST | `/api/auth/login` | เข้าสู่ระบบ (`login` = อีเมลหรือชื่อผู้ใช้) |
| POST | `/api/auth/forgot-password` | ขอลิงก์ตั้งรหัสผ่านใหม่ |
| POST | `/api/auth/reset-password` | ตั้งรหัสผ่านใหม่ด้วย token |
| POST | `/api/auth/logout` · `/api/auth/logout-all` 🔒 | ออกจากระบบเครื่องนี้ / ทุกเครื่อง |
| GET | `/api/me/sessions` 🔒 | อุปกรณ์ที่เข้าสู่ระบบอยู่ |
| DELETE | `/api/me/sessions/:id` 🔒 | ออกจากระบบอุปกรณ์ที่เลือก |
| POST | `/api/me/sessions/revoke-others` 🔒 | ออกจากระบบอุปกรณ์อื่นทั้งหมด |
| GET | `/api/medicines?q=&category=&limit=&offset=` | ค้นหายา |
| GET | `/api/medicines/categories` | รายการหมวดหมู่ |
| GET | `/api/medicines/:id` | รายละเอียดยา (+ เตือนแพ้ยาถ้าเข้าสู่ระบบอยู่) |
| PUT/DELETE | `/api/medicines/:id/favorite` 🔒 | ติดดาว / เลิกติดดาว |
| GET | `/api/medicines/favorites` 🔒 · `/recent` 🔒 | ยาที่ติดดาว / เปิดดูล่าสุด |
| GET/PUT | `/api/me` 🔒 | ข้อมูลส่วนตัว |
| PUT | `/api/me/settings` 🔒 · `/api/me/password` 🔒 | การตั้งค่า / เปลี่ยนรหัสผ่าน |
| GET | `/api/me/summary` 🔒 | ยาใกล้หมด นัดถัดไป จำนวนรายการ |
| GET/POST/PUT/DELETE | `/api/meds` 🔒 | ยาประจำ (+ `POST /:id/refill`) |
| GET/POST/PUT/DELETE | `/api/appointments` 🔒 | นัดหมาย (+ `GET /:id/calendar.ics`) |
| GET/POST/PUT/DELETE | `/api/allergies` 🔒 | ประวัติแพ้ยา |
| GET/POST/PUT/DELETE | `/api/vitals` 🔒 | บันทึกสุขภาพ |
| POST | `/api/ai/chat` 🔒 · `/api/ai/scan` 🔒 | แชท AI / อ่านฉลากยา |

## ระบบความปลอดภัย

| ส่วน | ทำงานอย่างไร |
|---|---|
| รหัสผ่าน | เข้ารหัสด้วย scrypt ไม่เก็บรหัสจริง ต้องยาวอย่างน้อย 8 ตัว และไม่รับรหัสที่เดาง่าย เช่น `12345678` หรือ `password...` |
| การเข้าสู่ระบบ | เซิร์ฟเวอร์ตั้ง cookie แบบ `HttpOnly` + `SameSite=Lax` (+ `Secure` ตอน production) JavaScript ในหน้าเว็บอ่าน token ไม่ได้ จึงกันการขโมยผ่าน XSS |
| เซสชัน | ทุก token ผูกกับแถวในตาราง `sessions` ออกจากระบบแล้ว token ใช้ไม่ได้ทันที ไม่ต้องรอหมดอายุ (7 วัน) |
| อุปกรณ์ | ผู้ใช้ดูได้ว่าเข้าสู่ระบบจากเครื่องไหนบ้าง และสั่งออกจากระบบเครื่องอื่นได้ (ตั้งค่า → อุปกรณ์ที่เข้าสู่ระบบ) |
| เปลี่ยน / รีเซ็ตรหัสผ่าน | เปลี่ยนรหัส = เครื่องอื่นถูกออกจากระบบ ส่วนรีเซ็ตรหัส = ทุกเครื่องถูกออกจากระบบ ลิงก์รีเซ็ตใช้ได้ครั้งเดียวภายใน 30 นาที และขอลิงก์ใหม่แล้วลิงก์เก่าใช้ไม่ได้ |
| กันเดารหัสผ่าน | ใส่รหัสผิด 5 ครั้งต่อบัญชี = ล็อก 15 นาที / ลองเข้าสู่ระบบได้ 30 ครั้งต่อ IP ต่อ 15 นาที |
| จำกัดการใช้งานอื่น | สมัคร 10 ครั้ง/ชม./IP, ขอรีเซ็ตรหัส 5 ครั้ง/15 นาที/IP และ 3 ครั้ง/ชม./อีเมล, API รวม 300 ครั้ง/นาที/IP, ถาม AI 30 ครั้ง และสแกน 20 ครั้ง/10 นาที/ผู้ใช้ |
| กัน CSRF | คำขอที่แก้ข้อมูลซึ่งส่งมาจากเว็บไซต์อื่นจะถูกปฏิเสธ (ตรวจ header `Origin`) |
| HTTP headers | `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS (ตอนใช้ https) และ API ตอบแบบ `no-store` เพื่อไม่ให้ข้อมูลสุขภาพค้างอยู่ในแคช |
| ตรวจการตั้งค่า | ถ้า `JWT_SECRET` สั้นเกินไปหรือยังเป็นค่าตัวอย่างตอน production เซิร์ฟเวอร์จะไม่ยอมเปิด |

ข้อจำกัด: ตัวนับจำกัดจำนวนครั้งเก็บในหน่วยความจำ จึงใช้ได้กับเซิร์ฟเวอร์ตัวเดียว (ซึ่งเป็นกรณีปกติเมื่อใช้ SQLite) และตัวนับจะเริ่มใหม่ทุกครั้งที่รีสตาร์ท

## Deploy ขึ้นใช้งานจริง

**สิ่งที่ต้องมี:** โฮสต์ที่รัน Node.js 22 ได้ และมี**ดิสก์ถาวร (persistent disk / volume)** เพราะฐานข้อมูลเป็นไฟล์ SQLite ถ้าไม่มีดิสก์ถาวร ข้อมูลผู้ใช้จะหายทุกครั้งที่ deploy ใหม่ แพลตฟอร์มแบบ serverless อย่าง Vercel หรือ Netlify Functions จึงใช้ไม่ได้

ตัวเลือกที่ใช้ได้ เช่น Railway (เพิ่ม Volume), Render (Web Service + Persistent Disk ซึ่งต้องใช้แพ็กเกจเสียเงิน), Fly.io (volume) หรือ VPS ทั่วไป

### Environment Variables ที่ต้องตั้งบนโฮสต์

| ชื่อ | ค่า |
|---|---|
| `NODE_ENV` | `production` |
| `JWT_SECRET` | สุ่มใหม่ 64 ตัว: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `TRUST_PROXY` | `1` (โฮสต์เกือบทุกเจ้ามี proxy อยู่ด้านหน้า) |
| `DB_FILE` | path บนดิสก์ถาวร เช่น `/data/paoya.db` |
| `APP_URL` | ที่อยู่เว็บจริง เช่น `https://paoya.up.railway.app` |
| `RESEND_API_KEY`, `EMAIL_FROM` | สำหรับส่งอีเมลรีเซ็ตรหัสผ่าน (สมัครที่ resend.com) ถ้าไม่ตั้ง ผู้ใช้จะรีเซ็ตรหัสเองไม่ได้ |
| `GEMINI_API_KEY` | ถ้าต้องการเปิด AI |

### วิธีที่ 1: รันด้วย Node.js โดยตรง

- Build command: `npm install`
- Start command: `npm start`
- Health check path: `/api/health`
- ผูกดิสก์ถาวรไว้ที่โฟลเดอร์เดียวกับ `DB_FILE` (เช่น mount ที่ `/data`)

### วิธีที่ 2: ใช้ Docker

มี `Dockerfile` ให้แล้ว ฐานข้อมูลจะอยู่ที่ `/data/paoya.db` ให้ผูก volume ไว้ที่ `/data`

```bash
docker build -t paoya .
docker run -d -p 3000:3000 -v paoya-data:/data \
  -e JWT_SECRET=... -e TRUST_PROXY=1 -e APP_URL=https://your-domain paoya
```

### ตรวจหลัง deploy

1. เปิด `https://โดเมนของคุณ/api/health` แล้วต้องเห็น `{"ok":true}`
2. สมัครบัญชี เพิ่มยาประจำ แล้วสั่ง deploy ใหม่หรือรีสตาร์ท จากนั้นเข้าสู่ระบบอีกครั้ง ข้อมูลต้องยังอยู่ (ถ้าหายแปลว่ายังไม่ได้ผูกดิสก์ถาวร)
3. ลองกด "ลืมรหัสผ่าน" ต้องได้รับอีเมลจริง
4. เปิดหน้าสแกนบนมือถือผ่าน https กล้องต้องเปิดได้

### สำรองข้อมูล

ข้อมูลทั้งหมดอยู่ในไฟล์ `paoya.db` ไฟล์เดียว ควรตั้งให้โฮสต์ทำ snapshot ของ volume หรือคัดลอกไฟล์นี้เก็บไว้เป็นประจำ

### เรื่องที่ควรทำต่อในอนาคต

- หน้าเว็บตอนนี้แปลง JSX ในเบราว์เซอร์ (Babel) ทำให้เปิดครั้งแรกช้ากว่าปกติประมาณ 1–2 วินาที ถ้าผู้ใช้เยอะขึ้น ควรย้ายไปใช้ระบบ build (เช่น Vite) แล้วจะเปิด Content-Security-Policy แบบเข้มงวดได้ด้วย
- ถ้าจะรันเซิร์ฟเวอร์หลายตัวพร้อมกัน ต้องย้ายฐานข้อมูลไป PostgreSQL และย้ายตัวนับจำกัดจำนวนครั้งไปเก็บใน Redis
